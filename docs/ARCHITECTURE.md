# Architecture

LabLink is a server-rendered Node.js application. Express owns HTTP routing and middleware, EJS renders pages, and SQLite stores the catalog, requests, and confirmed bookings. Browser JavaScript enhances forms and dialogs; core navigation and booking flows remain server-rendered.

## Request lifecycle

1. **Sign-in and roles** — `src/auth/` authenticates a provisioned account or starts an isolated demo persona. Role checks are enforced on the server, and state-changing forms require CSRF tokens.
2. **Discovery and requests** — `src/routes/catalog.js` and `src/routes/requests.js` validate HTTP input and call the booking functions in `src/booking/`. A pending request does not reserve a slot.
3. **Recommendation** — `src/scheduling/` ranks competing pending requests by fewest viable alternatives, then earliest deadline, then submission order. Eligibility and counts are calculated from database state, not generated by AI.
4. **Faculty decision** — `src/routes/faculty.js` presents the queue. `decideRequest` uses an immediate SQLite transaction and database constraints so two faculty actions cannot confirm the same slot.
5. **Optional AI** — `src/ai/` sends bounded, server-side Gemini requests for catalog matching and plain-language explanations. AI can explain or suggest; it cannot approve, reserve, or alter a booking.

## Runtime modes

| Command | Storage and access | Intended use |
|---|---|---|
| `npm run demo` | In-memory sample data; one-click student/faculty personas | Local product walkthrough |
| `npm run review` | In-memory data; public fixture accounts with password sign-in | Local password-flow review |
| `npm start` | Persistent local SQLite; administrator-provisioned users | Local development or controlled campus evaluation |
| Cloud Run container | Per-browser in-memory sandbox; no account database or Gemini key | Public, disposable demo only |

The Cloud Run mode is deliberately not a production deployment. It has bounded in-memory sandboxes and can reset on idle or instance restart. Do not enter real student or institutional data.

## Important boundaries

- `src/db/schema.sql` and `src/db/seed.js` define persistent structure and fictional sample data.
- `src/booking/` owns validation, availability queries, and transactional booking decisions.
- `src/scheduling/` owns deterministic conflict ranking and alternative selection.
- `src/routes/` adapts HTTP requests to application functions and EJS views.
- `test/` and colocated `*.test.js` files exercise isolated databases and stub external AI calls.
